# Begivenheder og API

## Hvad denne udviklerportal dokumenterer

| Overflade | Formål |
| --- | --- |
| **`window.INTA`** | Bootstrap-objekt **før** `uc.js` kører—policy-URL, domæne, firma, valgfrit `gtagId`, UI-muligheder ([JSON Schema](/docs/cookie-banner/javascript/inta-schema)). |
| **Integrationsmønstre** | GTM-affyringsrækkefølge, GA4, Meta, Google Consent Mode ([Integrationsoversigt](/docs/cookie-banner/integrations-overview)). |

Det er de **understøttede** integrationskontrakter til at bygge på inta.dev.

## Programmatisk JavaScript-API (runtime)

**Der dokumenteres ingen separat offentlig „CMP JavaScript API“ på denne portal** (ingen garanteret global som `window.IntastellarConsents.*` til produktion). Implementører bør:

- Styre adfærd via **`window.INTA`** og **`uc.js`** som dokumenteret.
- Bruge **Google Tag Manager** (eller jeres tag-lag) til events, triggers og leverandør-tags.
- Stole på **leverandør-samtykkemekanismer** (f.eks. Google Consent Mode, Meta-samtykkeparametre) hvor relevant.

Hvis jeres organisation udgiver en **versioneret runtime-API** til et bestemt CDN-build eller enterprise-niveau, tilføj dens kanoniske URL i frontmatter på denne side eller på [dokumentationsforsiden](/docs/cookie-banner), når den er stabil.

## Praktisk tjekliste

1. Valider samtykkestyret adfærd med **GTM Preview** eller jeres bundlers indlæsningsrækkefølge.
2. Brug DevTools (**Application** → cookies / storage, **Network**) for at bekræfte tags stemmer overens med samtykke **før** og **efter** valg.
3. Hvis noget kun må køre efter accept, udtryk det i **GTM-triggers** eller applikationskode der indlæses **efter** CMP—not via udokumenterede globals.

## Samtykkesignaler til tredjeparter

Intastellar Consents sender **samtykkesignaler** til understøttede stacks når konfigureret, så I ikke skal koble hver leverandør manuelt. Platformsspecifikke parametre følger stadig **Google**, **Meta**, **Microsoft** m.fl. — se [Integrationsoversigt](/docs/cookie-banner/integrations-overview).
