# Sådan virker det

Læs dette, når snippet’et fra [Hurtigstart](/docs/cookie-banner/quickstart) er på plads. Det forklarer **hvad der sker i browseren**, så GTM og leverandørtags bliver gennemskuelige.

## 1. Hvad der kører ved sidevisning (rækkefølge)

Hvert besøg følger grovt denne sekvens:

1. **HTML parses.** Tidligt `<head>`-indhold kører i rækkefølge.
2. **`window.INTA` kører**—kun konfiguration (policy-URL, domæne, firma, valgfrit `gtagId`, UI-indstillinger). Indlæser ingen tredjepartssporing.
3. **`uc.js` indlæses**—CMP-bootstrap fra `consents.cdn.intastellarsolutions.com`. Bør køre **før** analyse, annoncer eller pixels, der kræver samtykke.
4. **Resten af `<head>` og body**—GTM, `gtag`, Meta, embeds osv.

Kører trin 3 **efter** GA4 eller en pixel, kan cookies eller hits opstå **før** brugerens valg—svært at retfærdiggøre under GDPR-lignende regler og forvirrende i rapporter. Derfor kræver [Hurtigstart](/docs/cookie-banner/quickstart) **toppen af `<head>`**.

## 2. Sådan fungerer „blokering“ i praksis

„Blokering“ betyder her: **Ikke-nødvendig sporing må ikke opføre sig, som om besøgenden allerede har givet fuldt samtykke**, før de har interageret med banneret.

Det opstår **sammen** gennem:

| Del | Rolle |
| --- | --- |
| **CMP** | Viser UI, gemmer valg, anvender dokumenterede signaler på understøttede stacks. |
| **Indlæsningsrækkefølge** | For sent eller forkert rækkefølge gør CMP’en virkningsløs—se [Script lifecycle](/docs/cookie-banner/javascript/script-lifecycle). |
| **GTM-triggers og tag-samtykke** | Tags må ikke nøgent affyre på „All Pages“ før samtykke, medmindre jeres retsmodel udtrykkeligt tillader det. |
| **Leverandør-API’er** | Google **Consent Mode v2**, Meta-samtykkeparametre osv.—hver leverandør definerer adfærden. |

**Hardkodede** `<script src="https://…">`-tags i HTML bliver **ikke** automatisk omskrevet. I skal flytte dem **under** CMP eller **låse** dem (GTM, dynamisk efter samtykke).

## 3. Før besøgenden vælger

Indtil et valg er gemt (eller jeres setups defaults gælder):

- Marketing-/analyse-tags bør forblive **begrænset** eller **ikke** affyre som ved fulde annonce-/analyse-cookies—**afhængigt af GTM og leverandørkonfiguration**.
- Google-tags kan med Consent Mode, `gtagId` og passende defaults arbejde **samtykkebevidst** (inkl. begrænsede pings i Advanced Mode—se [Google Consent Mode](/docs/cookie-banner/google-consent-mode)).

## 4. Efter besøgendes valg

Når besøgenden accepterer, afviser eller vælger granulært:

1. CMP’en **gemmer** beslutningen (med forbehold for cookie-/lagerregler).
2. **Integrerede leverandører** modtager **opdaterede samtykkesignaler**, hvor konfigureret (fx Google Consent Mode med sat `gtagId` og korrekt wired tags).
3. **GTM** bør kun affyre afhængige tags, når triggers matcher den nye tilstand (brugerdefinerede begivenheder, samtykkechecks osv.).

**GTM / `dataLayer`:** Ved **ændring** af samtykke pusher banneret **`cookie_consent_update`** til `dataLayer`. I GTM bruger I en **Custom Event**-trigger med dette navn, så tags reagerer ved accept/afvisning/granulært—se [Begivenheder og API](/docs/cookie-banner/javascript/events-and-api). Der findes fortsat ingen dokumenteret global `window.IntastellarConsents.*`; tjek **Data Layer**-visningen i GTM Preview for den aktuelle payload-form.

## 5. Sådan modtager GTM og GA signaler

- **GTM:** Anbefalet mønster: **Custom HTML**-tag med samme `window.INTA` + `uc.js`-snippet, udløst ved **Consent Initialization – All pages**, **før** samtykkeafhængige tags. Se [Google Tag Manager](/docs/cookie-banner/google-tag-manager).
- **GA4 / Google Ads:** Med `settings.gtagId` og Consent Mode-bevidste tag-indstillinger tilpasser Google-tags sig samtykket i stedet for stille at være „fuldt til“.
- **Meta Pixel:** Samtykke via **Metas** muligheder og **jeres** trigger-timing—se [Meta Pixel](/docs/cookie-banner/meta-pixel).

## 6. Hvorfor måling ikke behøver at „gå i stykker“

Efter **afvisning** eller begrænset samtykke kan platforme som Google stadig vise **aggregerede eller modellerede** nøgletal (efter **deres** retningslinjer). Det er **ikke** det samme som ubegrænset personhenførbar sporing.

Efter **accept** kan fuld måling køre igen, **hvis** jeres container affyrer tags **efter** kendt samtykke.

Vi lover ikke „nul effekt på analytics“—vi dokumenterer **rækkefølge + Consent Mode + triggers**, så resultater bliver **forklarlige** og **verificerbare**.

## 7. Hvad CMP’en ikke gør

- Erstatter ikke **privatlivspolitik**, **leverandørliste** eller **juridisk** godkendelse.
- Retter ikke tags, der står **over** CMP’en eller ignorerer samtykke-API’er.
- Garanterer ikke overholdelse uden **jeres** korrekte konfiguration.
