# Script lifecycle (JavaScript)

Pour une installation minimale, suivez d’abord le [Démarrage rapide](/docs/cookie-banner/quickstart).

## Ordre de chargement

1. Définissez **`window.INTA`** dans un `<script>` inline dans `<head>`.
2. Chargez **`https://consents.cdn.intastellarsolutions.com/uc.js`** immédiatement après (voir [Démarrage rapide](/docs/cookie-banner/quickstart) ou [Premiers pas](/docs/cookie-banner/javascript/getting-started)).

Placer les deux **tôt dans `<head>`** réduit le risque que les balises d’analyse ou marketing s’exécutent avant l’initialisation de la CMP.

## Blocage et consentement

Les traceurs non essentiels sont **bloqués jusqu’au choix du visiteur** (accepter / refuser / granulaire, selon le produit). Après application :

- **Les métriques analytics et pub peuvent diminuer** par rapport à une configuration non contrainte. C’est **attendu** lorsque le consentement est appliqué honnêtement.
- Les balises qui respectent le Consent Mode (ou vos déclencheurs GTM) doivent toujours recevoir des **signaux de consentement corrects** après le choix pour que le reporting reste conforme.

## Stockage du consentement et preuve

Sur les niveaux **payants / plateforme**, les décisions de consentement peuvent être **journalisées** pour audit et reporting—voir [tarifs et offres](https://www.intastellarsolutions.com/solutions/cookie-consents#pricing) sur le site public. La bannière gratuite applique toujours l’UI et le blocage ; la rétention et l’export dépendent de votre offre.

## API JavaScript publique

Pour **GTM**, la bannière pousse **`cookie_consent_update`** vers **`dataLayer`** lorsque le consentement change—voir [Événements et API](/docs/cookie-banner/javascript/events-and-api). Pour d’autres hooks nommés ou une surface API programmatique complète, confirmez la référence la plus récente pour votre déploiement. Cette page documente la **configuration** (`window.INTA`) et l’**ordre de chargement** ; il n’y a pas de global documenté `window.IntastellarConsents.*` ici.
