# Google Tag Manager

Este guia é **direto**: um caminho claro que funciona na maioria dos sites. Você injeta o **mesmo** par `window.INTA` + `uc.js` do [Início rápido](/docs/cookie-banner/quickstart); o GTM só controla **quando** ele roda em relação às outras tags.

## Pré-requisitos

- Contêiner GTM instalado no site (`GTM-XXXX`).
- Valores prontos para `policy_link`, `rootDomain`, `company` e `gtagId` opcional (se usar tags Google com Consent Mode assistido pela CMP).
- Permissão para **publicar** uma versão do contêiner.

## Etapa 1 — Criar a tag CMP Intastellar

1. No GTM: **Tags → New**.
2. Tipo de tag: **Custom HTML**.
3. Cole **as duas** partes do [Início rápido](/docs/cookie-banner/quickstart):

   - `<script>` inline que define `window.INTA` (inclua `gtagId` em `settings` se usar GA4/Ads com este padrão).
   - `<script src="https://consents.cdn.intastellarsolutions.com/uc.js"></script>`.

4. **Advanced settings → Support document.write:** deixe **desligado**, salvo se o site exigir explicitamente.
5. Nomeie a tag claramente, ex.: `Intastellar Consents - CMP`.

## Etapa 2 — Trigger: Consent Initialization (obrigatório)

1. **Triggers → New**.
2. Tipo de trigger: **Consent Initialization – All pages** (em alguns workspaces: **Consent Initialization** com **All pages**).

Atribua este trigger **somente** à tag CMP da etapa 1.

**Por que importa:** Consent Initialization existe para que uma CMP rode **antes** de tags que se comportam como se o consentimento já estivesse concedido. Se sua tag CMP só usar um trigger **Page View** padrão que roda **depois** do GA4 na sequência, você verá hits ou cookies antes do consentimento—veja [Solução de problemas](/docs/cookie-banner/debugging).

## Etapa 3 — Tags Google: Consent Mode + configurações das tags

Se você usa **GA4**, **Google Ads** ou outras tags Google:

1. Defina `settings.gtagId` em `window.INTA` dentro da tag CMP (seu `G-XXXXXXXX` ou equivalente Ads conforme o [Início rápido](/docs/cookie-banner/quickstart)).
2. Na configuração GTM de cada tag Google, abra **Consent settings** (ou o equivalente da sua versão do GTM).
3. Alinhe o consentimento **default** e **update** à sua posição jurídica—não „conceda tudo“ por padrão sem alinhamento jurídico. Detalhes: [Google Consent Mode](/docs/cookie-banner/google-consent-mode).

## Etapa 4 — Tag de configuração GA4 (exemplo)

Os rótulos exatos da UI variam entre versões do GTM; a intenção é:

1. Tag **GA4 Configuration** (ou **Google tag**) com seu ID de medição.
2. **Trigger:** não um „All pages“ nu na primeira pintura **se** isso implica cookies de análise completos antes da CMP—prefira:

   - um trigger que dispare **após** o consentimento (ex. **Custom Event** quando sua política permitir análise), ou  
   - checagens **consent** nativas do GTM na tag para que ela respeite análise negada até atualização.

3. **Consent settings** na tag: exija os tipos de consentimento adequados para analytics storage / ad storage conforme o modelo Google.

Página GA4: [Google Analytics 4](/docs/cookie-banner/google-analytics-4).

## Etapa 5 — `cookie_consent_update` (quando o consentimento muda)

O banner envia um evento **`dataLayer`** chamado **`cookie_consent_update`** quando o visitante **altera** o consentimento (não só na primeira carga da página).

1. **Triggers → New → Custom Event**
2. **Event name:** `cookie_consent_update`
3. Use este trigger em tags que precisem rodar **naquele momento** (ex. push para outro sistema, tag que não basta só com Consent Initialization).

Combine com **Consent settings** das tags e documentação do fornecedor quando relevante. Inspecione evento e payload no **GTM Preview** após aceitar/recusar no banner—veja [Eventos e API](/docs/cookie-banner/javascript/events-and-api).

## Etapa 6 — Meta Pixel (exemplo)

1. Tag **Meta Pixel** (ou Custom HTML da Meta).
2. **Trigger:** dispara só quando o consentimento de **marketing/publicidade** for concedido no **seu** modelo—muitas vezes evento personalizado ou condição consciente de consentimento—não **All Pages** no carregamento antes da CMP.
3. Veja [Meta Pixel](/docs/cookie-banner/meta-pixel).

## Etapa 7 — Lista de verificação Preview (em staging)

1. **Preview** do contêiner; abra seu site.
2. Na linha do tempo do **Tag Assistant**, confirme que a tag CMP **Intastellar** dispara em **Consent Initialization** **antes** de GA4/Meta (se estiverem configuradas para esperar).
3. **Antes** de clicar em aceitar no banner: GA/Ads **não** devem se comportar como **plenamente consentidos**, salvo se você configurou os defaults assim de propósito (verifique no Preview + **Network**).
4. **Depois** de aceitar: devem aparecer requisições ou mudanças de modo esperadas.
5. Repita com **Reject** / consentimento mínimo para confirmar comportamento restrito.

## Etapa 8 — Publicar

Crie uma versão com uma nota, ex.:

`CMP: Intastellar on Consent Init; GA4/Meta gated by consent`

## Erros comuns

| Erro | Sintoma | Correção |
| --- | --- | --- |
| CMP só em Page View | GA4 antes da CMP na linha do tempo | Mover CMP para **Consent Initialization** |
| GA4 + `gtag.js` hardcoded | Hits duplicados / consentimento errado | Usar **um** caminho GA principal |
| „All pages“ no pixel | Meta dispara antes da escolha | Trigger de marketing só após consentimento |
