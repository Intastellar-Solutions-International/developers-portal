This guide covers **browser JavaScript** for Intastellar Sign-In when you **do not** use React. It **replaces** the former page at  
`developers.intastellarsolutions.com/identity/sign-in/web/docs/js-docs`  
— bookmark **inta.dev** instead.

Use **placeholders** (`your-client-id`, your real **app display name**, …) in your own code.

## Prefer React when you can

The supported path is [**`@intastellar/signin-sdk-react`**](https://www.npmjs.com/package/@intastellar/signin-sdk-react) — see [Intastellar Sign-In — React SDK and plain JavaScript](/docs/accounts-sign-in/web/integrating-react-and-javascript). It handles popups, **`postMessage`**, token verification, and cookies correctly.

## What the browser flow does

1. Open Intastellar’s **hosted sign-in** in a **popup** (`window.open` with a URL built from your **client id**, **app name**, **login/continue URI**, and **scopes**).
2. When sign-in succeeds, the popup sends a **string token** to the opener with **`postMessage`**.
3. The opener must **`postMessage` back** to the popup (`iframe-token-received` on the **popup’s origin**) so the hosted flow can finish — **this step is easy to miss** and breaks the flow if omitted.
4. The opener calls the **verify** API with that token (same as the SDK’s `IntastellarAPI.verifyToken`) and receives the **user** payload.
5. To match SDK behaviour, the opener typically stores the token in a **first-party cookie** on your domain so `getUsers`-style calls work on later page loads; otherwise treat the profile as one-shot and use **your own** backend session.

The open-source package implements this in `useIntastellar` — use it as the reference implementation:  
[github.com/Intastellar-Solutions-International/intastellar-signin](https://github.com/Intastellar-Solutions-International/intastellar-signin).

## npm package and “no React”

**`@intastellar/signin-sdk-react` declares `react` and `react-dom` as peer dependencies.** Installing it in a **non-React** app may still work for **`import { IntastellarAPI } from "@intastellar/signin-sdk-react"`** if your bundler installs peers, but you are outside the package’s primary support surface. Safer options:

- **Ship a tiny React tree** only for sign-in (button + provider), or  
- Ask Intastellar for a **documented standalone script / CDN** for vanilla pages, or  
- Reimplement the **same** `buildLoginUrl` + `postMessage` + `verify` + cookie steps using the SDK source as a spec (no copy-paste of production secrets).

## Illustrative opener script (bundler + peers satisfied)

The following mirrors the SDK’s **message** handler shape. **Validate `event.origin`** against the identity/popup origins Intastellar documents for your environment before trusting `event.data`.

```javascript
import { IntastellarAPI } from "@intastellar/signin-sdk-react";

const config = {
  appName: "Your registered app display name",
  clientId: "your-client-id",
  loginUri: `${location.hostname}${location.port ? `:${location.port}` : ""}${location.pathname}`,
  scopes: "profile,email",
};

export function openIntastellarSignIn() {
  const url = IntastellarAPI.buildLoginUrl(config);
  const popup = window.open(
    url,
    "intastellarLogin",
    "height=719,width=500,left=100,top=100,resizable=no",
  );
  if (!popup) {
    alert("Allow popups for this site to sign in.");
    return;
  }

  function onMessage(event) {
    const token = event.data;
    if (typeof token !== "string" || !token) return;

    // Acknowledge the popup — required for the hosted flow (same as the React SDK).
    if (event.source && "postMessage" in event.source) {
      event.source.postMessage("iframe-token-received", event.origin);
    }

    window.removeEventListener("message", onMessage);

    IntastellarAPI.verifyToken(token)
      .then((account) => {
        // account.user — e.g. name, email, image
        // Persist: SDK sets inta_acc cookie; or POST to your backend and set HttpOnly session.
      })
      .catch((err) => console.error(err))
      .finally(() => {
        if (!popup.closed) popup.close();
      });
  }

  window.addEventListener("message", onMessage);

  const timer = window.setInterval(() => {
    if (popup.closed) {
      window.clearInterval(timer);
      window.removeEventListener("message", onMessage);
    }
  }, 1000);
}
```

## Classic HTML + `<script src="…">`**

If you relied on a **hosted script** from the old developers site, get the **current** script URL and init API from **Intastellar** (support or console). Do not assume globals from an old domain after you redirect traffic to **inta.dev**.

If no CDN is offered, build **one bundled file** (option above) and load it from your own origin.

## After sign-in and logout

- **Backend session:** Prefer an **opaque HttpOnly cookie** after your server trusts the outcome — see [Sessions, cookies, and tokens](/docs/accounts-sign-in/web/sessions-and-cookies).  
- **Logout:** [Logout, errors, and troubleshooting](/docs/accounts-sign-in/web/logout-and-errors).

## Troubleshooting

- **Popup closes, nothing happens** — check **`postMessage` ack** and **origin** filtering.  
- **`getUsers()` empty** — no cookie / CORS / blockers; compare with SDK flow.  
- **Invalid hook call** — only if you use React components; see the package [**TROUBLESHOOTING.md**](https://github.com/Intastellar-Solutions-International/intastellar-signin/blob/main/TROUBLESHOOTING.md).
